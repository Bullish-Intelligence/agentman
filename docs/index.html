agentman documentation

agentman is a durable CLI and daemon for running typed agents. The central product promise is simple:

Every model call and tool call is recorded, always.

This documentation set has two jobs. It explains how the current code works, and it makes the remaining product and operations gaps visible. It should not quietly turn a design note into a claim that the feature is installed, deployed, or proven in production.

Read this first

Start with the overview . It defines the three user-facing nouns—agent, thread, and run—and gives the implementation status matrix.

Then choose a path:

  • I want to use it: Getting started , then the CLI reference .
  • I need to understand the system: Architecture , then Persistence and recovery .
  • I need to work on the repository: Development guide , then the architecture and persistence docs for the invariant being changed.
  • I want to know what is missing: Roadmap and gaps .
  • I want the proposed cross-tool design: ADR 0001: Record AI activity across local agents .

Status vocabulary

The docs use these terms deliberately:

  • Implemented means the behavior exists in this checkout and is covered by the relevant unit or integration tests.
  • Code-supported means the repository contains the implementation, but the surrounding machine or deployment setup is not part of this repository or is not active in the current development environment.
  • Verified means there is a named test or verification command for the behavior. It does not mean a production deployment has exercised it.
  • Pending means it is required for the intended operating model but has not been completed here.
  • Deferred means the design intentionally leaves it out until real use creates a reason to add it.

Source of truth

The implementation is under src/agentman/ and src/structured_agents/. Tests under tests/ are executable behavior evidence. The documents above explain the design and the current operational picture.

When a document and the current code disagree, document the difference in Roadmap and gaps , then update the appropriate source of truth.
