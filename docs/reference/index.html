CLI and configuration reference

Command summary

All commands run against the workspace resolved from the current directory. Inside a Git repository, the workspace is the resolved repository root; outside one, it is the resolved current directory.

CommandPurpose
agentman serveRun the daemon in the foreground
agentman serve --systemd-socketRun from one systemd-passed listening descriptor
agentman migrateApply packaged Alembic migrations
agentman versionPrint package and socket-protocol versions
agentman new [NAME]Create a thread, make it current, and switch to it
agentman use NAMESelect the most recently updated named thread
agentman lsList threads in the current workspace
agentman show [THREAD]Render a thread as Markdown; omitted means current
agentman statusShow current thread/run state and unresolved effects
agentman resume RUN_ID [--yes]Inspect, confirm, and resume a DBOS workflow
agentman configPrint resolved values and their sources
agentman send MESSAGERun one turn
agentman pipe [PREAMBLE]Read one turn from stdin
agentman pipe --each [PREAMBLE]Run one independent turn per stdin line

send and pipe accept --agent NAME, --model MODEL, --max-transport-retries N, and --json. --json suppresses live text deltas and prints the validated final result. --max-transport-retries sets the transport retry limit for one run. Zero allows one initial request and no transport retry. The option applies only to inferference: models. Omit it to keep the provider default.

Exact command behavior

CommandArguments and optionsBehavior
serve[--systemd-socket]Starts the daemon in the foreground. The systemd form requires exactly one passed listening descriptor.
migratenoneApplies packaged migrations; the daemon does not migrate during request handling.
versionnonePrints the installed package version and socket-protocol version.
new[NAME]Creates a thread, writes its id to the local current-thread file, and prints its short id and name.
useNAMESelects the most recently updated thread with that name and writes its id locally.
lsnoneLists all threads in the resolved workspace.
show[THREAD]With no argument, renders the current thread. With an argument, resolves it as a thread name, not an arbitrary id.
statusnoneReads the local current-thread pointer and prints status. With no pointer it prints no current thread and exits successfully.
resumeRUN_ID [--yes]Fetches the run, verifies its workspace, prints status, optionally confirms, and delegates resumption to DBOS.
confignonePrints resolved values and provenance, including inferference’s resolved router URL when applicable.
sendMESSAGE [--agent NAME] [--model MODEL] [--max-transport-retries N] [--json]Runs one turn. If no current thread exists, it creates an unnamed one.
pipe[PREAMBLE] [--agent NAME] [--model MODEL] [--max-transport-retries N] [--json] [--each]Reads all stdin. Without --each, stdin is one turn; with it, each physical line is an independent ordinary run.

For the pinned OpenAI software development kit (SDK), the omitted local-provider default is two retries. The SDK allows at most N + 1 physical attempts for one logical model request. The SDK retries only eligible failures. Agent-level output and tool retries remain separate. Each new logical request gets its own transport retry limit. Agentman does not fall back to another provider or model.

An explicit retry limit with another provider returns an error before the daemon starts a run. Run records expose the requested and effective limits, the fallback state, the logical turn count, and the physical request count. The physical count is null when the selected provider does not expose an instrumented transport path.

pipe accepts the optional-value forms -j, -jN, --jobs, --jobs=N, and --jobs N. The option may appear once and requires --each. A positive value sets the client-side in-flight bound; no value discovers inferference’s n_parallel value. A non-inferference model must use an explicit value.

For pipe --each, a trailing newline does not create an extra input, blank physical lines are inputs, results are emitted in input order, and a failed input is reported by its one-based input index. Text output is prefixed with [N]; JSON output emits one validated JSON value per successful input.

pipe --each

Examples:

printf '%s\n' alpha beta | agentman pipe --each
printf '%s\n' alpha beta | agentman pipe --each -j 2
printf '%s\n' alpha beta | agentman pipe --each -j
printf '%s\n' alpha beta | agentman pipe --each --json "Classify this"

Each physical stdin line is one prompt. A trailing newline does not create an extra record. A preamble is prepended to each line. Blank lines are records when they are present as physical lines.

  • -j N / --jobs N sets a positive client-side concurrency bound.
  • -j / --jobs without a value discovers n_parallel for an inferference model.
  • A non-inferference model requires an explicit job count when the bound cannot be discovered.
  • Results print in input order, with input indexes for text output.
  • --json emits one JSON result per successful input in input order.
  • A failed input is reported with its input index; successful submitted work is not hidden by a later failure.

Fan-out creates ordinary runs in one thread. It does not create a durable batch object and does not change daemon scheduling.

Configuration files

The configuration filename is agentman.yaml in two possible directories:

$XDG_CONFIG_HOME/agentman/agentman.yaml   global
~/.config/agentman/agentman.yaml          global fallback
<workspace>/.agentman/agentman.yaml       repository

The schema is flat. Precedence is:

CLI flag → repository config → global config → built-in default
KeyAllowed scopeMeaningDefault
agentglobal and repositoryDefault agent spec namedefault
modelglobal and repositoryDefault pydantic-ai model stringunset
database_urlglobal onlyDaemon and migration database URLunset, except AGENTMAN_DATABASE_URL
socketglobal onlyUnix socket path$XDG_RUNTIME_DIR/agentman.sock or /run/user/<uid>/agentman.sock
router_urlglobal onlyOptional inferference endpoint overrideinferference placement resolution

The repository file may contain only agent and model. Putting a global-only key in it is a configuration error. agentman config prints source provenance; when router_url is unset it also displays the URL inferference resolves.

Agent specifications

Agent files are .yaml or .yml files in .agentman/ or the global agentman directory. The filename stem is the fallback agent name. Repository specs shadow global specs with the same name.

The underlying mapping is a pydantic-ai AgentSpec. agentman removes these two extensions before passing the mapping to pydantic-ai:

name: reviewer
instructions: Review carefully.
output: models:Review
tools: coder

output: accepts either the literal str or a module:Attribute reference. The module is resolved relative to the spec directory in the repository’s interpreter. tools: currently accepts only coder; omitting it means no tools.

Every agent has an output type. If output: is absent, the type is str.

Thread and current-state files

The current thread pointer is stored locally at:

$XDG_STATE_HOME/agentman/current.json
~/.local/state/agentman/current.json   fallback

The file maps workspace paths to thread ids. It is a convenience pointer, not the durable thread identity; the authoritative thread and run records are in Postgres.

Exit codes

The CLI contract is stable and should be treated as an API:

CodeMeaningExamples
0SuccessTurn completed and output validated
1FindingOutput failed client validation; stream ended without a result
2Infrastructure/configurationSocket absent, database/router unavailable, unreadable config
3UsageUnknown command, malformed flag, invalid fan-out job count

Callers should not blindly retry code 1: the infrastructure may have worked and the model result may simply not satisfy the requested type.

Unix-socket HTTP API

The client uses HTTP over the configured Unix socket. The protocol version is 3. agentman version prints both the package version and protocol version; GET /v1/health reports the same values. The daemon currently exposes:

Protocol version 3 changes the request, response, and run record shapes. Protocol 2 clients and daemons are incompatible because the models reject extra fields. Upgrade the client and daemon together.

Method and pathRequestResponse
GET /v1/healthnonestatus, package version, and protocol version
POST /v1/turnsTurnRequest JSONSSE StreamEnvelope frames and one final turn_result or turn_error frame
POST /v1/threadsworkspace and optional nameThreadInfo
GET /v1/threads?workspace=...query parameterThreadList
POST /v1/threads/resolveworkspace and nameThreadInfo
GET /v1/threads/<id>path idThreadView
GET /v1/runs/<id>path idRunInfo

POST /v1/resumeworkspace and run idResumeResponse

Turn history is not sent as a messages field. The daemon loads it by thread id from the journal. TurnRequest.max_transport_retries is optional and must be non-negative when present. SSE frames carry the protocol version, run id, request and event ordinals, event kind, event payload, and a final-result flag. Clients must deduplicate replayed frames by the stamped ordinal tuple.

SSE delivery and failure semantics

SSE is a live presentation stream, not the durable record. The wire format is:

event: <envelope.kind>
data: <JSON StreamEnvelope>

The daemon keeps subscriber queues only for live connections. The current implementation starts the DBOS workflow before registering the request’s subscriber, so events emitted in that short window can be dropped. It does not replay missed events from Postgres into a later subscriber. The journal and stored snapshots are authoritative.

DBOS replay can cause an event to be observed more than once. The request and event ordinal tuple makes those duplicates removable by the client. This is different from dropped events: deduplication removes repeated delivery, but it cannot reconstruct a frame that was emitted before subscription or after the subscriber disappeared.

On success, the daemon drains live event frames and then emits one final turn_result envelope. If the workflow raises, it emits a final turn_error frame with a generic message. The CLI reports that as a finding (exit code 1); callers should inspect status and the durable run record rather than treating a failed turn as proof that no work occurred. A disconnected client loses its live subscription; DBOS owns the durable workflow and the daemon cleans up the connection’s subscriber and local wait tasks.

Important errors

  • A missing socket means the foreground daemon is not running in development.
  • A repository config containing database_url, socket, or router_url is invalid by design.
  • A missing output type module or invalid result is a client-side finding or configuration error, not a daemon-side import problem.
  • Inferference aliases are normalized by the shared capability resolver. Unknown models return HTTP 422. Router/capability failures return HTTP 503. SCHEMA is required only when the request includes an output schema; the default str output does not require it.
  • Resume refusals are HTTP 409 responses and CLI exit code 2. They cover unknown runs, terminal runs, missing workspaces, unreconciled effects, and requests whose workspace does not match the stored run. Both CLI and daemon workspace mismatch messages avoid disclosing the stored path.
